# 0005: pnpm instead of npm

- **Status:** accepted
- **Date:** 2026-11-04
- **Requirements:** REQ-PLAT-001

## Context

ADR 0001 chose npm as package manager. The user prefers pnpm.

## Decision

Use pnpm (version pinned in `package.json` `packageManager`, installed in CI by `pnpm/action-setup`).
The lockfile is `pnpm-lock.yaml`; CI installs with `--frozen-lockfile`. Scripts keep the same names.
Dependabot's `npm` ecosystem also covers pnpm lockfiles. The kith tarball is still a normal
dependency URL (ADR 0001).

## Consequences

- Strict `node_modules` layout: undeclared imports fail instead of working by accident.
- pnpm blocks dependency install scripts unless allowed; add an allowlist if a package needs one.
- pnpm 12's default `minimumReleaseAge` (1 day) is kept as supply-chain protection: a package released today cannot be installed until tomorrow.
- Contributors need pnpm (`corepack enable` or `npm i -g pnpm`).

## Alternatives considered

- Staying on npm: not preferred by the user.
